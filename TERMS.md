## 4. Responsible contribution

BELL PR helps you contribute to projects that other people maintain, often
in their spare time. When you use it, you agree to the following. <!-- claim:TERMS-14 -->

4.1 **You approve every pull request.** BELL PR publishes nothing until you
have marked every changed file as reviewed and approved the pull request
text, and it then opens the pull request as a draft. <!-- claim:TERMS-15 -->
Approve only changes that you understand and can explain, and be ready to
answer the maintainers' review. You are the author of what you publish. <!-- claim:TERMS-16 -->

4.2 **Follow each project's rules.** Read and follow the project's
CONTRIBUTING guide, code of conduct, pull request template, any Contributor
License Agreement (CLA) or Developer Certificate of Origin (DCO), and any
policy on AI-assisted contributions. Some projects do not accept
AI-assisted contributions at all; respect that. <!-- claim:TERMS-17 -->
BELL PR shows the contribution rules and templates it finds, with their
sources, but it can miss some, so check the project yourself. <!-- claim:TERMS-18 -->

4.3 **Sign only what you can certify.** BELL PR never adds a
`Signed-off-by` line or any other sign-off for you, and it refuses a
suggested description or commit message that contains one. <!-- claim:TERMS-19 -->
Add one yourself only if you can make the certification it stands for. <!-- claim:TERMS-20 -->

4.4 **Be open about AI assistance.** BELL PR can add an editable line to a
pull request description saying that the change was prepared with AI coding
agents and reviewed by you. The line is off unless you turn it on, for one
pull request or for all of them in Settings; when the project's own rules
ask for a disclosure, BELL PR quotes the rule and includes the line in its
suggested description. <!-- claim:TERMS-21 -->
Keep an accurate disclosure wherever the project asks for one. <!-- claim:TERMS-22 -->
In the app, text that AI models wrote, such as analyses, explanations and
answers, is labelled as AI-generated; check it before you rely on it. <!-- claim:TERMS-23 -->

4.5 **No bulk or unsolicited pull requests.** Do not use BELL PR to open
many pull requests across projects, to send changes that maintainers did not
ask for and are unlikely to want (such as mass reformatting, renames or
trivial fixes), or to inflate contribution counts. For anything beyond a
small fix, ask the maintainers first, for example in an issue. <!-- claim:TERMS-24 -->

4.6 **Follow the platforms' rules.** Follow GitHub's Acceptable Use
Policies and your AI provider's usage policies, including any limits on
automated activity. <!-- claim:TERMS-25 -->

If you use BELL PR in breach of this section, we may end your licenses under
section 16 of the EULA. <!-- claim:TERMS-26 -->
