Summary

  • BELL PR runs on your computer. There is no BELL PR cloud service and no BELL PR account.
  • BELL PR sends no telemetry, analytics or crash reports, and there is no license server. The app never contacts us.
  • Your code and your questions go only to the services you set up yourself: the AI provider behind the coding CLI you choose, and GitHub. They go there under your own accounts and those services' privacy policies.
  • Web access for agents is off unless you turn it on.
  • Everything BELL PR stores stays in its data directory on your computer, and you can delete it from the app.

What BELL PR does not do

  • It sends no telemetry, usage analytics, crash reports or diagnostics to us or to anyone else. It does not check for updates either.
  • It uses no license server. License keys are checked offline on your computer; activating a key, removing it or starting the trial sends nothing anywhere.
  • Its web interface loads nothing from other sites. Fonts and icons are bundled with the app (self-hosted), and its content security policy blocks requests to other sites.
  • It does not store the passwords and tokens of the tools it runs. git, the GitHub CLI, the Codex CLI and Claude Code keep their own sign-ins; BELL PR only asks them whether you are signed in.

What leaves your computer, and where it goes

BELL PR runs command-line tools that you installed and signed in to. Those tools send data to their providers under your accounts. Each provider's own terms and privacy policy decide what it keeps, for how long, and whether it may use the data to train models. The tools may also send their own usage data to their providers; BELL PR neither adds to that data nor turns it off. BELL PR starts each agent CLI with only the environment variables it needs to run and sign in, and starts the Codex CLI without its config.toml, so a usage-data setting that you made in another environment variable, or in that file, does not reach the agents BELL PR runs.

The AI coding CLI you choose

Contribution runs, project analysis, discovery, explanations, follow-up questions, pull request drafts, maintainer-feedback coaching, conflict resolution and follow-up rounds use the OpenAI Codex CLI or Claude Code. The CLI sends data to its provider: OpenAI for the Codex CLI, and Anthropic for Claude Code, or the cloud platform you set Claude Code up to use, such as Amazon Bedrock, Google Vertex AI or Microsoft Foundry. It sends:

  • the instructions BELL PR writes for each task, including the contribution direction you describe and the plan you approved;
  • source code and other files of the repository you imported: the files the agents open, the excerpts BELL PR selects for project analysis, diffs, and the project's contribution guidelines and pull request template;
  • the output of the commands the agents run in the working copy, such as builds and tests;
  • the questions you ask about a change, with the diff, explanation and review reports they refer to;
  • the review comments and check results of your pull request, when you ask for maintainer-feedback coaching or start a follow-up round;
  • for discovery, your search interests and the public details, documents, open issues and comments of the GitHub repositories that the search found.

Before BELL PR saves run logs, agent answers, your questions and team messages, it masks text shaped like a credential, such as GitHub tokens, API keys, license keys and private keys. It does the same with the context of a pull request draft before an agent sees it.

GitHub, through the GitHub CLI and git

Under your GitHub account, BELL PR:

  • clones and fetches the repositories you import, and reads their details, issues, contribution guidelines and templates;
  • searches GitHub for projects, when you run discovery;
  • reads the review comments and check results of your pull requests, when you ask for maintainer-feedback coaching;
  • writes only after you approve: it creates a fork when needed, pushes a branch and opens a draft pull request with the title, description and commits you approved, and later pushes only the follow-up commits you approved. It never force-pushes.

Commits carry the git name and e-mail address you configured, and they become public on GitHub. The app asks you to confirm, once per address, before it publishes a commit e-mail address that is not a GitHub no-reply address.

Web access for agents (off by default)

Web access is a Pro feature that you turn on in the AI provider settings. While it is on, the agents that work on a contribution (the team, the mentor that answers your follow-up questions, conflict resolution and follow-up rounds) can search the web and read web pages through the AI CLI's own web tools. Project analysis, discovery, explanations and pull request drafts never get it. Search queries go to the provider's search service. With Claude Code, agents may open pages only on github.com, docs.github.com and raw.githubusercontent.com; the Codex CLI uses OpenAI's own web search. The run log records the queries and addresses, not the page contents. Agents are told not to put repository contents, file paths or secrets into queries, but that is an instruction to an AI model, not a guarantee: leave web access off for confidential code.

What BELL PR stores on your computer

BELL PR keeps its data in one data directory: ~/.bellpr by default, or the directory you choose with --data-dir or BELLPR_DATA_DIR. BELL PR keeps the directory at permissions 0700, so other user accounts cannot read anything in it, and creates its files readable by your user account only.

While a run works, Git may also keep short-lived temporary files in the data directory. BELL PR deletes them when the step is done, or at the next start after a crash.

Your browser also keeps some data for this local site only: the language you chose, the contribution you opened last, layout preferences and the sample project's progress (in local storage), a note that the page reloaded once after an update (in session storage), and a sign-in cookie that is valid for 30 days.

If you set BELLPR_LICENSE_KEY, the key is also wherever you set that variable.

The working copies of cancelled and failed runs are removed automatically 14 days after their last activity, or after the retention period you set in Settings (1 to 365 days). Runs in review, approved runs and published runs keep their working copy until you free it, because reviews, follow-up rounds and syncing need it. The run records stay until you delete them.

Deleting your data

In the app you can free a run's working copy, delete a run, and remove an imported repository together with BELL PR's clone and its cached analysis. "Delete all data" in Settings erases every project, run, analysis, discovery result, log and backup at once; it keeps your settings, your license and the running server's own files. To remove everything, stop BELL PR, delete the data directory, and clear the site data that your browser keeps for BELL PR's address.

Data you sent to GitHub or to an AI provider is under that service's control. Delete it there under that service's policies, for example by closing a pull request or deleting a fork. We never receive your project data, so we cannot delete it for you.

License keys

A license key is checked offline against a public key built into the app. The key contains a license ID, the plan, the number of seats, and dates: the issue date, and either the end of the update period or, for subscriptions, the expiry date. It contains a name and an e-mail address only if the seller embeds them when issuing the key; keys from a pre-issued pool contain neither. The key stays on your computer, in license.json or in BELLPR_LICENSE_KEY. The app shows its name and e-mail address, when it has them, in the License section of Settings, in the About dialog and in bell-pr license status. Logs record only the license ID and the plan.
